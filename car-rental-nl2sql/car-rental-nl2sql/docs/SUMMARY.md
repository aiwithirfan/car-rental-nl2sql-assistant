# Written summary

**What I built.** A natural-language-to-SQL assistant for a family-owned car rental company. A manager asks a
question in English; the system builds a prompt from the database schema, asks an LLM for one SQLite query,
validates it, executes it read-only and shows both the answer and the SQL. A Streamlit app exposes it, and a
benchmark of 50 questions measures how often the answer is right.

**Key decisions and why.**
1. *Execution accuracy on result sets, not SQL text* - two different queries can both be correct, and a query
   that looks right can return wrong numbers. Gold answers are computed once from gold SQL.
2. *Layered safety instead of one filter* - the prompt tells the model to refuse, a tokenising validator
   allows only a single SELECT, SQLite is opened with `mode=ro`, an authorizer whitelists the business tables,
   and a timeout plus a row cap stop runaway queries. Any one layer failing is not enough to harm the data.
3. *Never retry around a guardrail* - the retry loop only handles ordinary SQL errors, and the SQLite error
   message is fed back to the model. A blocked query ends the attempt.
4. *Rich schema prompt* - column descriptions, foreign keys, sample rows and business definitions (what "late"
   or "overdue" means) are included because most text-to-SQL mistakes are misunderstandings of the data, not
   of SQL.
5. *A frozen "today"* (2025-12-31) so date questions have one reproducible answer.
6. *Ablation* - the retry loop, the schema richness and the model are removed or swapped one at a time to
   measure what each contributes (`docs/ABLATION.md`).

**Evidence.** 58 automated tests pass; the 50 gold queries all execute and return data; 13 of 13 unsafe
requests are blocked (`results/guardrail_log_validator.csv`); LLM accuracy and the ablation table are generated by
`scripts/make_report.py` into the README.

**Limitations and next steps.** The data is synthetic and single-turn only; the keyword validator is
conservative; failure labels are heuristic. With more time I would add conversation memory, an AST-based
validator, retrieval of few-shot examples, and a larger benchmark with confidence intervals.
